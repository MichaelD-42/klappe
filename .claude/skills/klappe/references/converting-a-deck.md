# Converting a deck

Use this when someone hands you an old presentation (PPTX or PDF) to turn into a klappe deck. The result is a draft: sections, `scene.md` steps with notes, chart numbers in `data/` with their source, picture links for `media/TODO.md`, and a `CONVERSION.md` with the slide map and the open questions. It has no `scene.ts`; motion comes after, in [building a deck](building-a-deck.md). Each step ends before the next one starts.

1. Ask the deck owner, before you read the file: the deck id, the language, the planned length in minutes, and whether the content is confidential (`confidential: true` in `deck.md`: no picture prompt or text leaves the machine). Then run `node klappe/bin/klappe.mjs init --deck <id>` in the deck repo, unless the deck exists.
2. Extract into a scratch folder outside the deck, with the system tools only (no npm package). If one is missing, name it and stop: never guess a slide's content from its title.
   - PPTX: `unzip -o talk.pptx -d <scratch>/pptx`. The slide order is `ppt/presentation.xml` (`<p:sldIdLst>`, resolved through `ppt/_rels/presentation.xml.rels`), not the file numbers. Text is in the `<a:t>` runs of `ppt/slides/slideN.xml`; a slide with `show="0"` is hidden. Speaker notes are the `notesSlide` its `ppt/slides/_rels/slideN.xml.rels` links. Pictures are in `ppt/media/`. Chart numbers are in `ppt/charts/chartN.xml`: per `<c:ser>`, the name in `<c:tx>`, the categories in `<c:cat>`, the values in the `<c:v>` of `<c:val>`.
   - To see the slides: `soffice --headless --convert-to pdf --outdir <scratch> talk.pptx`, then `pdftoppm -r 50 -png <scratch>/talk.pdf <scratch>/slide`, and read the PNGs.
   - PDF: `pdftotext -layout -f N -l N talk.pdf -` per page, and `pdftoppm` as above. A PDF has no notes and no chart data: a number you read off a page is marked for checking (step 5).
3. Map slides to scenes before you write one. A chapter (a divider slide, or a run of slides on one theme) is a section. One scene carries one message: split a slide that makes two points, merge a run of build slides that make one, drop the agenda and "thank you" slides unless the owner wants them. Write the map as a table at the top of `decks/<id>/CONVERSION.md`: slide number, section/scene id, and what happened (kept, split, merged, dropped and why). Scene ids are unique in the whole deck.
4. Write each `scene.md`: the `## title`, then one list item per step with a few words on screen; the rest of the slide's text and its speaker notes go into `> note` lines under the step that needs them. Add `story:` in the frontmatter, the one sentence the room takes away. Use what Markdown does by itself ([markdown](klappe/docs/reference/markdown.md)) instead of describing it: a chart link, a table with ✓ and ✗, a code or console fence, agenda rows, task lists, `:icon-name:` on an item, `layout: big-number` for a slide that is one number. A diagram of boxes and arrows is not a picture to copy: name the element that redraws it (`flow`, `process`, `sequence`, ...) in `CONVERSION.md` for the build step.
5. Put every chart's numbers in `data/<scene>-<what>.csv`, header row first, and a `# source:` line: the original source if the slide names one, else the file and slide (`# source: talk.pptx, slide 7`). A number read off a PDF page says so (`# source: talk.pdf p. 7, read from the page, check`). Never invent or round a number; a figure without a source is an open question, and the scene keeps the link so `data/TODO.md` lists it.
6. Pictures: copy the deck's own photos and screenshots from `ppt/media/` to `media/` under a name that says what they show, and link them as `![alt](media/<name>)`. For a picture you cannot copy (stock art, a logo you have no file for, a slide that needs a new picture), leave the link with alt text and a prompt in the title, `![A crowded release board](media/board.png "A kanban board with too many cards in progress")`; `npm test` lists it in `media/TODO.md`. Never write a placeholder file.
7. Fill `deck.md` (title, lang, duration, theme) and check: `npm run outline` reads as the talk, one message per scene, against the planned length; `npm run outline -- --story` reads as one arc; `npm test` has no deck problem apart from the missing pictures and data you listed.
8. Finish `CONVERSION.md` under the map with the open questions, one per line with its scene's deep link: numbers without a source, pictures to supply, slides dropped, elements to choose for the diagrams, anything in the notes that contradicts the slides. Hand it back to the owner and wait for the answers before the build.
