# Backlog

Open work only, ranked, most important first. All of it is in scope for 1.0.0, which is the last entry; the first entries change the deck format, the API or the look, so they come before anything builds on them. CHANGELOG.md lists what is done and git history has the old lists. A defect is fixed test-first: if its test already passes, the entry was stale and is dropped.

- API audit against the three work decks: which `klappe/fx` effects and options they used, which they worked around, which none touched. Unused effects are candidates to merge or drop before 1.0 freezes them; the same count re-ranks this list from use, not ideas.
- Type scale tokens: `--k-size-title`, `--k-size-body`, `--k-size-label` (names to settle), so a theme sets the hierarchy, not only colours and faces. The effects in `src/fx` set font sizes as literals in about 74 places; retrofitting them breaks looks, so land it before 1.0. Add a design lint rule against new size literals.
- Text steps replace, not stack: by default a plain list item in `scene.md` gets the stage to itself, set large, and leaves when the next one comes; stacking becomes the opt-in. Today `renderDefault` and `defaultStep` in `src/render/world.ts` fade each item in and keep it, the bullet build-up slide. Changes existing decks: a CHANGELOG **Changed** line, before 1.0.
- Frame size: a deck sets its frame (4:3, 9:16, square), not only 1920x1080. Scene coordinates, the camera, the overview cards, `shot` and `pdf` all assume 16:9, so decide before 1.0. Vertical frames matter once video export exists.
- `template/`: the starter deck `klappe init` copies, replacing the one-scene starter it writes inline in `bin/klappe.mjs` today. Take its shape from the three work decks: the sections, `deck.md` keys and `data/` and `media/` layout they each ended up with. Accept (spec M4): a fresh session in a new deck repo builds a scene from a storyboard and gets a green `klappe test`.
- Word cap by default: the template sets `max-words` (about 12), so a long step fails `klappe test` from the first scene. The check exists; no deck sets it, the demo neither.
- The template's docs name `npm run klappe:sync` for skill updates (the open TODO in DECISIONS.md, 2026-10-16).
- Interactive review edits: with the review window open, select an element on the stage and drag, resize or nudge it, its scene coordinates shown live. A preview only: it never touches the timeline and goes on the next step. On release it writes a structured line to the step's Visuals finding in `review.md` (element, step, from rect, to rect); Claude applies it in the source and marks it fixed, the owner approves, as review mode does today. Not a direct write-back: a position in `scene.ts` is code (a loop, a helper, `place()`, an earlier tween), and only a reader can tell which number to change. Text from `scene.md` can be edited in place and written straight back. Spike first: in dev, each `klappe/fx` call records its call site (`scene.ts:12`) on its root from a stack trace; check that Chromium's line numbers hold through Vite's transform, else fall back to effect name and text.
- `svg`: authored full-colour SVG (Figma, Illustrator, Inkscape export) with its fills kept, layer ids addressed per step (`show`, `draw`, `light`, `dim`). Colours map to `--k-*` tokens, by class (`k-accent`) or a map from the file's hex values, so the art follows the theme and the contrast check; a colour with no mapping and a step id the file lacks are deck problems. Ship an export guide with it. Today `lineArt` forces every shape to an `--k-fg` outline (`src/fx/draw.ts`).
- Overlay layer: content that does not live on the canvas and stays fixed on screen while the camera moves, with its own steps: lower thirds, a chapter label, a source line, a logo. Titling builds on it. Check first how the stage's frame chrome and `safe-area` would hold it, and how the self-test and `shot` see it.
- Motion tempo: the step, camera and auto-hold times come from `motion = { camera: 1.6, step: 0.6, autoHoldMs: 2500 }` in `src/theme.ts`, fixed for every deck. Let a theme or `deck.md` set them (a slower board talk, a quicker demo day). The deck-wide side of Camera pacing.
- Camera pacing: an ease and a duration per flight (today `addCameraMove` in `src/camera.ts` always eases `power2.inOut`), and a whip mode, a fast flight with motion blur between far scenes. A slow push-in, a whip and a hard stop give a deck a tempo.
- Handout export: a `pdf` option for one page per scene, at its last step, with the speaker notes under it, for sending after the talk.
- Rehearsal timing: a rehearsal mode in the speaker view that records the time spent per scene and shows it against the plan (`duration` in `deck.md`, the `outline` estimate), so the talk's slow parts show from real runs.
- Own visualization recipe: a catalog scene and a skill section for a chart `chart` lacks, built in `scene.ts`: d3 into `ctx.svg`, data from `ctx.files.data`, colours from tokens, one reveal per step, seek equal to play. No doc or demo scene shows it today.
- Own icons: an `icons/` folder in the deck or deck repo, SVGs normalised to Lucide's 24-unit stroke grid, used by name in `icon()` and `iconTile()` like a Lucide icon. For corporate and product glyphs; brand logos stay in the deck (trademarks), not bundled.
- Deck arc: a deck-level rubric in `.rubrics/` for the content reviewer (an opening hook, a through-line, set-ups paid off, one ask at the end), and a story view in `klappe outline` that prints each scene's story point in order. Needs the story point in `scene.md` frontmatter, not only in the storyboard outside the deck.
- Video export: `klappe video` renders a deck to MP4 by stepping each canvas timeline frame by frame in Playwright, holding each step for its `auto` time or a default. Seek equals play, so a frame is exact; wall-clock loops (backgrounds, `mesh3d`, video) need their own clock in this mode. Check first whether the frames can feed ffmpeg without a new npm dependency.
- Titling: a lower third (a name and role, or a quote's source) and an end roll of sources and thanks, built from the sources the deck's charts already record.
- Composition presets: named layouts in `scene.md` frontmatter beyond the default column and 45/55 text-and-media split (a rule-of-thirds split, a full-bleed picture with a caption, a big number with a footnote). An agent picks a named layout more reliably than it places pixels.
- Section rhythm: a `section.ts` token override (an inverted or dark section, a picture section between diagram sections), so a deck can pace like a magazine. Today the theme is per deck.
- Type as image: one word or number set to fill the frame, edge to edge, optionally with a picture or video showing through the letters. `shout`, `kpi` and `counter` stay at text sizes; no effect clips media to text.
- Brand theme: from a logo and two brand colours, derive a full `--k-*` theme that passes the contrast rules. The logo and footer go in the Overlay layer.
- Spacing and shape tokens: gaps, corner radius and stroke weight as `--k-*` tokens, so a brand with sharp corners and wide whitespace can say so.
- Deck cuts: one deck in several lengths (a 20- and a 45-minute cut that leave sections out) and a backup appendix outside the main flow, one jump away for Q&A. Today a re-cut means a copied deck.
- Presenter ink: draw on the stage during the talk (a laser dot, and a pen that marks and fades), from the mouse or the speaker view. Live, so it sits under `data-k-ignore` and never on a timeline; clear it on the next step.
- Icons in Markdown: `:icon-name:` on a list item in `scene.md` sets an icon with the step. Pairs with Text steps replace, not stack. Check first whether `image` already shows a `.svg` as a plain picture.
- Establishing shot: a step that pulls the camera out to the whole canvas, then pushes into the next scene. An authored move on the timeline, not the `O` overview.
- Monotony check: a look warning when several scenes in a row are text only or share one layout. The walk knows each scene's parts.
- Own transitions: `section.ts` `transition` takes a function as a background's `animate` does, with the same `reveal` label contract, so a deck has its own transition without forking klappe. Today `TransitionKind` is a closed union of twelve.
- Deck conversion: turn a PPTX or PDF into a draft deck folder (sections, `scene.md` steps, notes, `data/` for chart numbers with their source, `media/TODO.md` for the pictures). Probably a skill workflow over the `klappe` skill, not engine code; the storyteller prompt's "Convert deck" step is the spec.
- Pictogram chart: units drawn as icons ("1 in 4 engineers") that fill step by step, from `waffle` and `icon`.
- Layout grid: a column grid that scenes place on, or a look check that flags near-misses across scenes (a title a few px off where the other scenes put it). The `shot --sheet` contact sheet shows drift; nothing checks it.
- Image treatment: a duotone or tint on `image` from the theme's tokens, so photos from different sources read as one set.
- Split screen: two scenes side by side, the camera cutting between each alone and both together. Check first whether `place()` and a camera frame round both already do it.
- Handheld drift: a barely visible wall-clock drift of the camera while a step holds, under `data-k-ignore` like the backgrounds. Off with reduced motion; check whether it suits `calm` at all.
- Deck components in Markdown: a deck registers a fence or trigger for its own helpers (the demo's `speakerProfile`, `planChip`), so `scene.md` can use them without `scene.ts`.
- Sound: a short cue on a step (a whoosh on a flight, a hit on `impactShake`) and a music bed under a section. Plays on a forward step only, silent on seek, jump and back, like video; opt-in per deck and muted by a key. Reverses a v1 non-goal in the design spec (decided 2026-10-30, see DECISIONS.md); the build adds its own DECISIONS entry on how it keeps the timeline rule.
- klappe's own words per deck: a strings override in the deck for a language `src/strings.ts` lacks (it has `en` and `de`).
- `klappe dev` crashes when a scene folder is renamed or moved. The `virtual:klappe-langs` watcher reads the old `scene.ts` path, throws ENOENT, and the server exits. Skip files that no longer exist. Seen in the training deck review on 2026-10-28, with several builders sharing one `klappe dev` server, as were the six defects below.

- A running `klappe dev` does not pick up a new scene folder. `shot --url` then fails with "no step matches", while `outline` and `test` see the scene. A restart fixes it.
- `shot --last` with a step target (`<section>/<scene>/<step> --last`) reused an old PNG without a warning. A builder reported it; not reproduced yet. Shoot the given step, or reject the mix.
- `test --only` with several targets prints one test file and three tests, so the output does not show which scenes were walked. List them.
- `klappe test` does not fail fast when the deck cannot load. With a syntax error in one `scene.ts`, each `--only` walk waited about 230 s for `script#klappe-selftest`, then failed with a TimeoutError (four walks, 15 min of agent time). Fail within seconds on a compile or load error, and print the error.
- `shot --help` prints no help: it renders every scene of the deck (3 calls, about 9 min).
